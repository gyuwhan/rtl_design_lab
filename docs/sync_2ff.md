# sync 2ff

## 필요한 이유

- 입력 신호와, 신호를 받는 모듈의 clk의 위상 관계를 모를 경우,입력 신호가 모듈의 setup, holdtime에 바뀌어 metastable 한 출력이 나갈 수 있다. 따라서 입력값이 내부에서 안정될 시간이 필요한데, ff을 1단 추가해 ff1의 tc2q부터 ff2의 setup까지 약 1사이클 동안 안정될 시간을 확보할 수 있다.

## 1. 사양

- 포트: input(clk/1, rst_n/1, d_async/1), output(q_sync/1)
- 리셋: Sync reset, Active low, clk이 동작중이고, rst_n은 clk에 동기.
ff1 = 0, ff2 = 0, q = 0
- 지연: 입력 변화 후 2번째 수신 엣지에 q_sync 갱신 + 메타스테빌리티로 변화 이전 값에 안정되면 3번째 엣지에 갱신
- Async input을 받아, 2ff의 동작 clk에 sync된 신호 출력
- 한 엣지의 hold 끝 ~ 다음 엣지의 setup 시작 사이에 발생하는 펄스, 메타스테빌리티에 따라 펄스 신호는 무시될 수 있음
- `tclk - tc2q(ff1) - tsetup(ff2)` 동안 안정화 시간 확보
- 실패 확률을 완전히 0으로 만들지 못하고, 멀티비트 일관성을 보장하지 않음

## 2. 예측표

입력은 setup/hold를 벗어나 바뀜, 값은 각 에지 직후 기준.

| 에지 | d_async | ff1 | ff2 / q_sync |
|---|---|---|---|
| E1 | 0 | 0 | 0 / 0 |
| E2 | 0 | 0 | 0 / 0 |
| E3 | 1 | 1 | 0 / 0 |
| E4 | 1 | 1 | 1 / 1 |
| E5 | 1 | 1 | 1 / 1 |
| E6 | 0 | 0 | 1 / 1 |

## 3. TB 확인 목록

| 무엇 | 조건 | 기대 결과 |
|---|---|---|
| 리셋 동기 동작 | `q_sync = 1`일 때 에지 사이에서 `rst_n = 0` | 다음 에지 전까지 `q_sync = 1` 유지, 그 에지 후 `ff1 = 0`, `q_sync = 0` |
| 리셋 중 입력 무시 | `rst_n = 0`, `d_async = 1` | 에지가 지나도 `ff1 = 0`, `q_sync = 0` |
| 리셋 해제 | `d_async = 1` 상태에서 `rst_n = 1` | 해제 후 1번째 에지에 `ff1 = 1`, 2번째 에지에 `q_sync = 1` |
| 0→1 지연 | 에지와 겹치지 않게 `d_async` 0→1 후 유지 | 변화 후 2번째 에지에 `q_sync` 0→1 |
| 1→0 지연 | 에지와 겹치지 않게 `d_async` 1→0 후 유지 | 변화 후 2번째 에지에 `q_sync` 1→0 |

확인 못 하는 것: 메타스터빌리티 발생과 안정되는 값, 그로 인한 3번째 에지 지연, MTBF(Mean Time Between Failures: 평균 고장 간격). 일반 RTL 시뮬레이션에서는 setup/hold 구간에 입력을 바꿔도 메타스터빌리티가 재현되지 않는다.

## 5. 검증 결과

- 시나리오 11단계 PASS (`make sim`, 140ns)
- 버그 A, 비동기 리셋: 10단계에서 `ff1`, `q_sync` 2건 FAIL (131ns)
- 버그 B, 1단 구조: 2, 4, 7단계에서 `q_sync` 3건 FAIL
- 확인 못 한 것: 메타스터빌리티 발생, 3번째 에지 지연, MTBF

## 6. 펄스 유실 실험

### 조건

- 수신 클럭: 40MHz, 주기 25ns
- posedge: 12.5, 37.5, 62.5, 87.5, 112.5, 137.5, 162.5, 187.5, 212.5, 237.5, 262.5, 287.5, 312.5, 337.5, 362.5ns
- 리셋: 50ns까지 rst_n = 0, 이후 1
- 입력: 평소 d_async = 0, 아래 구간에서만 1

| 경우 | d_async = 1 구간 | 폭 | 펄스 안의 posedge | ff1 = 1 구간 | q_sync = 1 구간 |
|---|---|---|---|---|---|
| A | 65~75ns | 10ns | 없음 | 없음 | 유실 |
| B | 110~120ns | 10ns | 112.5 | 112.5~137.5 | 137.5~162.5 |
| C | 190~220ns | 30ns | 212.5 | 212.5~237.5 | 237.5~262.5 |
| D | 285~315ns | 30ns | 287.5, 312.5 | 287.5~337.5 | 312.5~362.5 |

- 위치와 상관없이 RTL 시뮬레이션에서 posedge가 최소 하나 걸리려면 펄스 폭은: Tclk(25ns) 이상 (입력 변화가 에지와 겹치지 않을 때)
- 실제 회로에서 깨끗한 샘플이 최소 하나 있으려면 펄스 폭은: Tclk(25ns) + setup + hold 초과, 설계 여유를 두면 수신 주기의 약 1.5배

### 실험 결과

- TB 12개 시점 확인 PASS (375ns)
- A(10ns): 펄스 안에 posedge가 없어 `ff1`, `q_sync`가 변하지 않음. RTL 시뮬레이션으로 관측한 펄스 유실
- B(10ns): 같은 폭이지만 posedge가 걸려 `q_sync`에 25ns 펄스로 전달
- C, D(30ns): 같은 폭이지만 걸린 posedge 수에 따라 `q_sync` 폭이 25ns, 50ns로 다름
- 이벤트 간격 조건: 두 펄스 사이의 0 구간도 수신 클럭에 샘플링되려면 두 펄스 사이 최소 1개의 posedge에 샘플링되어야 한다. 따라서 최소 간격은 RTL 시뮬레이션에서는 Tclk(25ns) 이상, 실제 회로에서는 Tclk(25ns) + setup + hold 초과여햐 함
- 확인 못 한 것: 메타스터빌리티로 인한 유실, MTBF
